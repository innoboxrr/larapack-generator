Estructura que genera larapack:model-view dentro del paquete.

El modulo Vue vive junto al backend y se publica como paquete npm propio, de
forma que la API y su interfaz viajan y se versionan juntas. El anfitrion lo
descubre por glob de Vite; no hay que enumerar rutas en ningun indice global.

resources/vue/
    package.json                    -> paquete npm "packageName" (una vez)
    vite.config.js                  -> build en modo libreria (una vez)
    index.js                        -> punto de entrada: exporta routes (una vez)
    src/
        routes/
            index.js                -> agrega ../models/*/routes/index.js (una vez)
        models/
            <kebab-del-modelo>/
                index.js            -> contrato del modelo: sin framework
                store/
                    index.js        -> store Pinia
                routes/
                    index.js        -> rutas del modelo (vue-router 4)
                forms/
                    CreateForm.vue
                    EditForm.vue
                    FilterForm.vue
                views/
                    AdminView.vue   -> indice + router-view de las hijas
                    CreateView.vue
                    EditView.vue
                    ShowView.vue
                widgets/
                    DataTable.vue
                    ModelCard.vue
                    ModelProfile.vue

Contrato con el backend
-----------------------

  index.js            API_ROUTE_PREFIX = 'api.<dotNamespace><snake_del_modelo>.'
  RouteServiceProvider ->as('api.<dotNamespace><archivo_de_rutas>.')

Los dos tienen que coincidir: el front resuelve cada URL por nombre de ruta
con innoboxrr-route-resolver, que lee el routes.json que genera
`php artisan route:json` (innoboxrr/routes-to-json).

El array `actions` que emite el Resource de Laravel alimenta las acciones por
fila del datatable: `route: true` navega a params.to.name desde el menu de la
fila; `route: false` invoca model[callback](params), asi que el callback tiene
que ser un export real de index.js.

Como se usa
-----------

  El indice deja la tabla montada: el alta se abre en un drawer encima, y al
  guardar se recarga la tabla en su sitio, sin perder pagina, orden ni
  filtros. El detalle abre la edicion en otro drawer sobre la ficha. Las
  rutas conservan sus nombres, asi que un enlace a AdminCreate... o
  AdminEdit... abre el drawer que toca. Ctrl+K abre la paleta de comandos.

Requisitos del anfitrion
------------------------

  - JsonResource::withoutWrapping() en el AppServiceProvider. El codigo
    generado espera el recurso plano, no envuelto en { data: ... }.
  - ToastRegionComponent y ConfirmHostComponent montados una vez: ahi se
    pintan los avisos y la confirmacion antes de borrar o exportar.
  - window.route y las traducciones inicializadas en el bootstrap.
